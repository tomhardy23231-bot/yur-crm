# Тесты Юр CRM

Три уровня. Чем выше — тем быстрее и дешевле; чем ниже — тем ближе к реальному
поведению пользователя.

| Уровень | Папка | Раннер | Что проверяет | Нужна инфраструктура |
|---|---|---|---|---|
| **Юнит** | `tests/unit` | Vitest | Чистая логика (даты ЗП, сальдо кассы, diff журнала, форматтеры, маппинг ошибок) | нет |
| **Интеграция** | `tests/integration` | Vitest | RLS (права доступа), триггеры денег, ставки/расчёт ЗП, воронка этапов, книга операций | Neon-БД из `.env.local` |
| **E2E** | `tests/e2e` | Playwright | Реальный браузер: вход, защита маршрутов, app-shell | dev-сервер (поднимет сам) + учётка owner |

## Команды

```bash
npm test                 # юнит-тесты (быстро, без БД) — дефолт
npm run test:unit        # то же
npm run test:watch       # юнит в watch-режиме
npm run test:integration # интеграционные (БД из .env.local)
npm run test:e2e         # E2E (Playwright сам поднимет dev-сервер на :3210)
npm run smoke:rls        # смоук RLS/триггеров на живой БД (см. ниже)
```

## Предусловия

**Интеграция** (цикл v4 — Neon, Supabase больше нет): нужны только
`DATABASE_URL_APP` + `DATABASE_URL_ADMIN` в `.env.local`. Тесты
**самодостаточны**: строят свой namespace (`IT-<runId>-…`) через admin-пул,
проверяют от лица обычных сессий (`userDb`) и **убирают за собой** — безопасны
на любой живой БД (dev-ветка, клон прода). Если переменных нет — наборы
помечают себя `skipped`, а не падают.

**E2E** логинится владельцем. На сидовой базе (`npm run db:seed`) подходят
дефолтные креды (`owner@yur.local` / `test12345!`, см. `scripts/seed.ts`);
на любой другой базе передай свои через env:

```bash
E2E_OWNER_EMAIL=... E2E_OWNER_PASSWORD=... npx playwright test tests/e2e/auth.spec.ts
```

- Playwright поднимает СВОЙ dev-сервер на порту `:3210` (`E2E_PORT`) — рабочий
  dev-сервер на `:3001` не трогается. Первый прогон медленнее — Turbopack
  компилирует маршруты на лету (таймауты в `playwright.config.ts` это учитывают).
- Перед E2E один раз поставить браузер: `npx playwright install chromium`.
- `core-flow.spec.ts` — сквозной денежный флоу (клиент → дело 10000 → платёж
  4000 → «Оплачено/Борг»), активирован 2026-07-27. Созданные записи
  (`E2E-…`) остаются в БД — прибирает владелец учётки; юрист и Експерт в деле
  должны быть РАЗНЫМИ людьми (иначе поверх карточки всплывает модалка
  «Суміщення ролей» и перекрывает модалку платежа).

## Смоук RLS (`npm run smoke:rls`)

`scripts/smoke-rls.ts` — быстрый ручной прогон ПОСЛЕ МИГРАЦИЙ: 20+ секций
PASS/FAIL (каталог RLS всех доменных таблиц, fail-closed, воронка, платежи,
ставки, ступенчатые права). С 2026-07-27 **самодостаточен**: строит мир на тех
же фикстурах (`tests/helpers/fixtures`), убирает за собой в `finally` и не
зависит от сидовых логинов и ставок — безопасен на любой живой БД, включая прод.

## Что НЕ покрыто (кандидаты на расширение)

- Server Actions создания/правки (клиент, дело, платёж) напрямую — позитив +
  отказ по правам (транзакционные контракты покрыты интеграцией, e2e жмёт формы).
- E2E по ролям (юрист/Експерт), акты и касса в браузере.

Книга операций (расходы, счета, зарплата→касса, отчёты, конвертация «витрат»,
грант-матрица, справочник статей) покрыта `tests/integration/money-book.test.ts`
(30 тестов) + юниты `expense-cleanup.test.ts` (2026-07-27).
